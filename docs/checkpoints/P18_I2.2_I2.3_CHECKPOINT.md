## 3d. M4 — DNS resolution + IP pinning (code + chứng minh)

**Đã tạo** (`lib/import/ssrf/`):
- `dns.ts` — `resolveAndVerify(hostname, resolver)`: **resolve-once** lấy toàn bộ A/AAAA; kiểm **mọi** địa chỉ theo L2, **bất kỳ địa chỉ bị cấm ⇒ chặn toàn bộ** (không thử địa chỉ khác); chọn IP đầu (ưu tiên IPv4). Fail-closed: resolver lỗi → `DNS_FAILED`; rỗng → `NO_ADDRESSES`; IP literal nội bộ → `UNSAFE_ADDRESS`. Cổng `DnsResolver` (tiêm được) + `SystemDnsResolver` mặc định.
- `pinned-request.ts` — `pinnedRequest()`: gửi HTTP/HTTPS qua `lookup` tuỳ biến trả **đúng IP đã xác minh** ⇒ tầng socket **KHÔNG** resolve lại hostname (chống DNS rebinding/TOCTOU). Giữ `host` = hostname gốc (HTTP `Host` header) và `servername` = hostname gốc (**SNI** + xác minh chứng chỉ theo hostname gốc, `rejectUnauthorized: true`). Đếm byte body, vượt `maxBytes` ⇒ huỷ + `BODY_TOO_LARGE`; timeout ⇒ `TIMEOUT`; lỗi TLS ⇒ `TLS_FAILED`. Trả `remoteAddress` (địa chỉ peer thật) để test kiểm chứng. **Không** follow redirect (L6 ở M5).
- `index.ts` — barrel mở rộng.

**Hạ tầng test:** `vitest.security.config.ts` (node env, `tests/security/**`, timeout 30s, chạy tuần tự); `vitest.config.ts` loại trừ `tests/security/**`; script `test:security`.

**Test** (`tests/security/ssrf-pinning.test.ts`, **11 test — INTEGRATION, socket thật**):
- **(1)+(2) Pin chứng minh:** request tới hostname **không có DNS** (`recipe.test`) vẫn kết nối được tới `127.0.0.1`; đo `remoteAddress === "127.0.0.1"` + server nhận `Host: recipe.test` (không phải IP). **CONTROL:** cùng hostname KHÔNG pin ⇒ thất bại (đã loại trừ khả năng "thành công nhờ DNS thật").
- **Phân biệt IP:** pin `127.0.0.2` ⇒ server B nhận, server A `seen.length === 0`.
- **(3) TLS/SNI:** cert tự ký CN/SAN `recipe.test` (tạo bằng `openssl`): SNI = `recipe.test`, `remoteAddress` pin đúng; cert sai hostname (`evil.test`) ⇒ `TLS_FAILED`.
- **(4) resolveAndVerify:** mixed public/private ⇒ `UNSAFE_ADDRESS`; toàn public ⇒ chọn IPv4; IPv6 nguy hiểm kèm IPv4 public ⇒ chặn; rỗng ⇒ `NO_ADDRESSES`; resolver lỗi ⇒ `DNS_FAILED`; IP literal nội bộ ⇒ `UNSAFE_ADDRESS`.

**Kết luận:** ✅ **IP pinning CHỨNG MINH** — kết nối đi tới đúng IP đã xác minh, HTTP client không tự resolve lại, TLS/SNI giữ hostname gốc. Blocker **B1/B-I2-01** giải quyết (chuyển PENDING → RESOLVED cho môi trường Node).

**Kiểm chứng:** `pnpm typecheck` ✅ PASS; `pnpm test:security` ✅ 11/11 PASS; `pnpm test` ✅ 485/485 PASS (không hồi quy).

## 3e. M5 — Redirect protection + response limits (code)

**Đã tạo** (`lib/import/ssrf/safe-fetcher.ts`) — lớp `SafeFetcherImpl implements SafeFetcher`:
- **L1/L2/L5/L7:** gọi lại `SsrfUrlValidator` cho **mỗi** hop (không tin URL nguồn trả về).
- **L3/L4:** `resolveAndVerify` (resolve-once, kiểm mọi A/AAAA) + `pinnedRequest` (pin IP) — cổng `TargetResolver`/`PinnedRequester` tiêm được.
- **L6 redirect:** KHÔNG auto-follow; tự theo ≤ `maxRedirects` (mặc định 5); resolve Location tương đối; **kiểm lại toàn bộ URL + resolve/pin lại mỗi hop**; phát hiện loop (tập `visited`); 3xx thiếu Location ⇒ `HTTP_ERROR_STATUS`.
- **Chính sách HTTPS:** `requireHttps` (mặc định true) chặn hạ cấp http ở mọi hop (kể cả URL gốc).
- **L8 response:** ngân sách timeout tổng (deadline − elapsed truyền vào `pinnedRequest`); trần byte **sau giải nén** (`decodeBody` dùng `maxOutputLength` của `zlib` — chống compression bomb); allow-list content-type (mặc định `text/html`, `application/xhtml+xml`); 4xx/5xx ⇒ `HTTP_ERROR_STATUS`.
- **L10:** header gửi đi là hằng `SAFE_REQUEST_HEADERS` (chỉ accept/accept-encoding=identity/user-agent) — **không** Cookie/Authorization; không tái sử dụng header giữa các hop.
- **L11:** mọi lỗi trả mã AN TOÀN (không lộ IP/DNS/stack).

**Tiện ích tách riêng (test được):** `decodeBody()` (ánh xạ encoding→giải nén, identity/unknown), `baseContentType()`.

**Tinh chỉnh nhỏ:** `SsrfUrlValidator` nhận tuỳ chọn `{ allowedPorts }` (mặc định `{80,443}` giữ nguyên policy; chỉ nới cho harness test cổng động).

**Test mới** (`tests/security/safe-fetcher.test.ts`, **20 test**):
- *Integration (socket thật):* theo redirect tương đối (redirectChain/ finalUrl); redirect **khác domain** vẫn **không gửi Cookie/Authorization** + giữ `Host`=hostname đích; vượt 5 redirect ⇒ `TOO_MANY_REDIRECTS`; loop ⇒ `REDIRECT_LOOP`; body >trần ⇒ `BODY_TOO_LARGE`; **compression bomb** ⇒ `DECOMPRESSION_LIMIT`; content-type lạ ⇒ `UNSUPPORTED_CONTENT_TYPE`; 404 ⇒ `HTTP_ERROR_STATUS`; server im lặng ⇒ `TIMEOUT`.
- *Logic (requester/resolver tiêm):* redirect tới hostname → IP nội bộ ⇒ `UNSAFE_ADDRESS`; hạ cấp HTTPS→HTTP ⇒ `URL_REJECTED`; 3xx thiếu Location; DNS lỗi ⇒ `DNS_FAILED`; header gửi đi không chứa cookie/authorization + có `accept-encoding: identity`.
- *Unit:* `decodeBody` (identity/gzip/identity-vượt-trần/gzip-vượt-trần/encoding lạ), `baseContentType`.

**Kiểm chứng:** `pnpm typecheck` ✅ PASS; `pnpm test:security` ✅ **31/31 PASS** (M4 11 + M5 20); `pnpm test` ✅ 485/485 PASS; `pnpm exec eslint` ✅ sạch.

## 4. Tiền đề I2.3 — spike cơ chế IP pinning (nay đã vào code ở M4)

Spike cục bộ (`spike-pin.mjs`, `spike-pin2.mjs`, tạm) đã chứng minh trên Node `v24.1.0`:
- `node:http`/`node:https` với option `lookup` (custom resolver) **pin IP** đã kiểm (hostname không có DNS vẫn kết nối tới IP chỉ định; `lookupCalls=1`).
- Phân biệt IP đích (`127.0.0.1` vs `127.0.0.2` → hai server khác nhau) ⇒ kết nối đi **đúng** IP đã chọn.
- **TLS/SNI** giữ hostname gốc (server thấy `servername=recipe.test`); cert sai hostname bị từ chối (`ERR_TLS_CERT_ALTNAME_INVALID`).
- `undici` **không** là dependency dự án ⇒ dùng `node:http`/`node:https` built-in.

> Đây là tiền đề cho M4; phần **chứng minh chính thức bằng integration test** (đo địa chỉ kết nối thực tế) đã hoàn tất ở **M4** (§3d).
